# Future SV input schema

Use the three JSON Schema files for event catalogue records, accession-level calls and the sample/accession crosswalk. TSV files accepted by `validate_future_sv_data.py` must use the schema property names as column headers. Required event fields: candidate_id, event_id, reference_assembly, chromosome, start, end, coordinate_convention, sv_type, event_length, source_provenance. Optional event fields include REF/ALT or event sequence, deleted/flanking sequence, breakpoints, graph/alternate IDs, methods, validation, quality metrics and limitations. Required call fields: candidate_id, event_id, sample_id, accession_id, genotype_pav, missing_call and source_provenance; quality/depth/filter metadata are optional but recommended. Required crosswalk fields: sample_id, accession_id and source_provenance; alternate IDs and exact match method are recommended.

Accepted coordinate conventions are explicitly `1-based-closed` and `0-based-half-open`. Accepted call strings include 0/1/2 dosage; diploid 0/0, 0/1, 1/1 phased or unphased forms; presence/absence labels; and explicit missing labels. Missing state and missing_call flag must agree. The validator requires a unique sample ID mapping and consistent assembly/event definition. Accessions may have multiple distinct sample IDs if documented. A schema passing check establishes formatting consistency only, not biological validity or event identity. `--self-test` uses temporary synthetic parser fixtures explicitly labeled SYNTHETIC TEST ONLY and removes them after testing; those are never written into project data or result tables.
